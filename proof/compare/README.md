# P1: one attack, four controls

```sh
uv run python -m proof.compare.run
```

The results are committed in `RESULTS.md`, regenerated by the run; a test
fails if the committed file differs from a fresh run.

## The attack

An agent with valid credentials obtains an approved intent (18,000 INR to
vendor V-100) and its own process changes the amount or the payee before
sending. Credentials, headers, and request shape are unchanged. The attacker
mints a fresh idempotency key, because the caller controls that header. This
is the gap every "the human approved it" story has: approval happens in one
place, the bytes are sent from another.

## How each control is modelled, and what would make it catch the attack

| Setup | Modelled as | Catches | Would catch this if |
|---|---|---|---|
| a) LLM guardrail stub | Content filter over the tool-call text, run at approval and again on the outgoing request | Injection phrases, exfiltration phrases, card-number shapes | It compared the outgoing request to the approved one. Then it is no longer a content filter; it is binding. |
| b) API gateway | API-key auth plus an OPA-style rule `amount < cap`, cap 50,000 | Invalid callers, amounts above the cap | The cap were below 48,000, which also refuses the approved 18,000 (footnote 1 in RESULTS.md, pinned by a test). Thresholds classify amounts; they do not know what was approved. |
| c) Idempotency key | Strict deduplication: same key with a different body is rejected | Reuse of a key, replay of a request | The attacker reused the approved key. The attacker mints a fresh one. |
| d) PrivateVault receiver gate | The real `ReceiverGate`, permit minted for the approved bytes | Any difference between the approved bytes and the arriving bytes, and any reuse | It already does. |

A gateway can only catch this by verifying a signed approval bound to the
exact request bytes, which is what PrivateVault's receiver gate does.

## Fairness

Every control also receives the honest request first and admits it; a
control that refused everything would not be a comparison. The guardrail
is not a no-op: a request whose text contains an injection phrase is
refused (pinned by a test). The gateway and idempotency models are the
strict versions of what they claim to be.

## What this does not show

That any particular vendor's product behaves like these models. They are
the mechanisms, implemented plainly, with their assumptions stated above.
